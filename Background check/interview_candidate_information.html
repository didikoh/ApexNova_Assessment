Weakness: sometimes I can spend too much time refining technical details because I want the solution to be well implemented. I have improved this by prioritising tasks based on business requirements and deadlines.

I enjoy working with colleagues who communicate clearly, take responsibility for their work, and are open to discussion and feedback.

16. How do you handle disagreement or conflicting opinions within development team? Can give an example of how do you resolve the situation in the past?

I normally first try to understand why each person prefers a particular solution instead of immediately deciding which person is right or wrong.

For example, when there are different opinions about how to implement a web or interactive feature, I compare the approaches based on requirements, development time, maintainability, performance and user experience. If necessary, I will create a small proof of concept or test the different approaches.

Then we can make the decision based on technical evidence and project requirements rather than personal preference.

17. What steps do you take to stay updated with the latest trends and technologies in full stack development?

I regularly read official documentation, GitHub repositories, release notes and technical discussions.

I also like to build small proof-of-concept projects when learning new technologies because I find hands-on testing more effective than only reading documentation.

Recently I have also been using AI development tools to help with technical research, compare different approaches and learn new frameworks more efficiently.
